# Founder Town — instructions for Claude Code

2D pixel-art social world (top-down 3/4 view) for startup founders. Built so far: **engine + asset pipeline + layered characters**, **accounts + onboarding** (Supabase), **multiplayer lobbies** (Colyseus), **proximity voice + video calls** (WebRTC) and the **office studio** (owners lay out departments in their private lobby). Other game systems (pills, missions, chat) come later — don't build them unless asked.

Full spec: `docs/spec.md`. Read it before changing anything in `shared/src/spec.ts`, the layer system or the asset pipeline.

## Stack
- pnpm workspaces: `shared/` (pure TS), `client/` (Vite + Phaser 3 + React), `server/` (Colyseus 0.18, run with tsx), `supabase/` (SQL migrations), `scripts/` (asset tooling, run with tsx), `art/` (source art)
- TypeScript strict everywhere. Vitest for `shared/`. Playwright (via `/tmp`-style scripts) for visual checks.

## Commands
- `pnpm dev` — run client (http://localhost:5173) + server (:2567); `pnpm dev:client` / `pnpm dev:server` for one of them
- `pnpm start:server` — production server
- `pnpm test` — unit tests (shared logic)
- `pnpm typecheck`
- `pnpm assets` — placeholders (missing files only) → map (if missing) → validate
- `pnpm assets:validate` — enforce the pixel spec on every asset; must pass before committing art
- `pnpm tsx scripts/preview-avatar.ts` — render composed avatars to `docs/previews/`
- `pnpm tsx scripts/preview-office.ts` — render every department (starting size + a larger one) to `docs/previews/office.png`
- `pnpm assets:export` — export real Aseprite art (needs Aseprite CLI)

## Architecture rules (do not break)
1. **Rendering never owns state.** `client/src/state/store.ts` is the single client store. Phaser views read logic objects; they never mutate them.
2. **Logic vs view split.** `entities/Character.ts` (logic, no Phaser) vs `entities/CharacterView.ts` (render). Same pattern for anything new.
3. **`shared/` is pure.** No Phaser, no DOM, no Node APIs. Movement, collision, pathfinding, avatar schema, palette swap and map parsing live here so the future server runs the same code.
4. **Input → intents.** `InputController` produces directions/clicks; the scene applies them to logic.
5. **The map is data.** Rooms, collisions, furniture, spawns and zones come from Tiled (`client/public/assets/maps/`). Never hardcode world content in code. Two maps, both generated by `scripts/gen-map.ts --force` and edited in Tiled after that: `town.tmj` (the main lobby: open office, kitchen, library, lounge, meeting room) and `office.tmj` (a private lobby: one empty 40×26 room). What an owner builds in their office is data too — an `OfficeLayout` laid over `office.tmj` (see Office & studio).
6. **UI is React over the canvas.** Panels, menus and builders are DOM, not Phaser.

7. **The network is a layer, not a dependency of the UI.** Only `client/src/net/` talks to Supabase, Colyseus or WebRTC. It mirrors remote state into the store and exposes actions; React and Phaser read the store and call those actions. The wire contract (message names, payloads, voice radii) and the onboarding questions live in `shared/` (`protocol.ts`, `founder.ts`) and are imported by both sides.

## Accounts, lobbies, voice (`client/src/net/`, `server/src/`)
- **Config:** one `.env` at the repo root (see `.env.example`), read by the client and landing page (Vite `envDir: ".."`) and by the server (`server/src/env.ts`, which also accepts the `VITE_` names). Supabase key = the publishable key (`VITE_SUPABASE_PUBLISHABLE_KEY`; `…_ANON_KEY` still works). With no Supabase keys both sides run in **guest mode** (no sign-in, profile in localStorage) — development only; the server refuses it in production unless `ALLOW_GUESTS=1`.
- **Session (`net/session.ts`):** Supabase Auth (Google OAuth, email + password, password reset). `store.session.status`: loading → signedOut / recovery → onboarding → ready; the game and the room start at `ready` (`main.tsx`). The `profiles` row (`supabase/migrations/0001_profiles.sql`, RLS: own row only) holds name, time zone, picture, avatar, onboarding answers and `lobby_code`; it is loaded into the store on sign-in and store changes are written back (debounced). UI code never calls Supabase.
- **Onboarding (`ui/Onboarding.tsx`):** the first time, the questions are followed by the avatar builder as the last step (`EditAvatar` with `intro`: a full `.screen`, opens on the starter characters, Back / Enter Founder Town); the account is marked onboarded only when that step is done. Editing the answers later (`edit`) has no avatar step. The questions are full screen (`.ob`), in the game's look: `TownScene` (a slice of the office built from the real terrain tiles, plant prop and the avatar compositor at a whole-number scale, with your live name tag and picked answers) + a question panel with 12×12 pixel icons (`PixelIcon.tsx`, one per option id, game palette). `.ob` opts out of `--ui-scale` so the art lands on whole pixels. 3 steps rendered from `STAGES` / `GOALS` / `HEARD` in `shared/src/founder.ts` — a new option needs an icon with the same id; also the "founder" modal for editing. Stage, one-liner and goals are synced to the room and shown on player cards. Goal chips on both profile cards (`GoalChips` in `PixelIcon.tsx`) carry the same icon at 12 screen px (counter-zoomed like `.sprite`).
- **Room (`net/room.ts` ↔ `server/src/TownRoom.ts`):** one room type `town`, `filterBy(["lobby"])`. Lobby = `main` or a private code (`profiles.lobby_code`; knowing the code is the access, link = `?lobby=<code>`). `onAuth` verifies the Supabase token and that the lobby exists (`lobby_office` RPC, run as the user — the server has no service key; it also says whether the caller owns the lobby and returns the saved office). State = `players` map (name, avatar JSON, founder fields, tile, dir, speaking, cam) + `office` (JSON of the lobby's layout). The client mirrors it into `store.players` (unchanged players keep their object identity) and `store.office`. The lobby picks the map on both sides: `mapOf(lobby)` → `town` (main) or `office` (private).
- **Movement:** the client predicts and sends every step (`move`); the server checks adjacency + `canStep` on the same map file + a walking-speed budget, and answers `snap` when it disagrees. Remote players are `Character`s walking (pathfinding) toward their last reported tile. NPCs are gone.
- **Sitting:** a chair is a **seat**, not an obstacle — prop property `seat` = the direction you face on it (`SEATS` in build_props.py → `props.json` → tile property), footprint 0. `parseWorld` / `buildWorld` list seats in `world.seats` and mark their tiles in the grid (`isSeat`): you can step onto one, and `findPath` goes around seats unless one is the goal. Whoever stands still on a seat's tile sits: `CharacterView.setSeat` hops the sprite up, turns it the seat's way and draws it just behind the chair (head and shoulders over the chair's back). It is derived from the tile on every client — nothing about sitting is sent or stored. There is no sitting art: the pose is the idle frames behind the chair.
- **Voice/video (`net/voice.ts`):** WebRTC mesh; the room only relays signaling (`rtc`) and call handshakes (`call`). You are connected to everyone within `VOICE.connect` tiles plus everyone you are in a call with; mic and camera go to all connected peers; proximity volume fades with distance, call peers are full volume. Each connection has one audio + one video transceiver negotiated once; mute/camera use `replaceTrack` (never renegotiate). Smaller session id makes the offer. Speaking = mic level → `speaking` flag in room state → sound bars on the name tag (`NameTag.setSpeaking`).
- **TURN:** `GET /ice` (`server/src/ice.ts`) trades the Cloudflare Realtime TURN key (`CLOUDFLARE_TURN_KEY_ID` / `CLOUDFLARE_TURN_API_TOKEN`, server-only) for 24 h credentials, shared for 1 h, signed-in users only. `voice.ts` fetches them at start and every 12 h (STUN until then); `VITE_ICE_SERVERS` overrides it.
- **Invites:** `InviteDialog` (link + email). `POST /invites` on the server sends through Resend when `RESEND_API_KEY` is set; otherwise the client opens a `mailto:`.
- **Routes (`client/src/router.ts`):** one client page serves `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/onboarding`, `/play`, `/play/<lobby>`, `/studio/<lobby>`; the session status picks the screen and the router keeps the address bar on the matching path (`replaceState`) — in the town that is the lobby we are in, and `/studio/<lobby>` while the studio is open (a studio link opens the studio once joined, if the lobby is yours). A lobby code rides along as `?lobby=` on auth/onboarding paths so invites survive sign-in. Asset URLs use `import.meta.env.BASE_URL` (the client builds with base `/app/`, dev uses `/`).
- **Deploy (Railway project `founder-town`):** both services build a Dockerfile named by the service variable `RAILWAY_DOCKERFILE_PATH` (Railway ignored `railway.json`, so there isn't one).
  - `web` → `thefoundertown.com` (+ `www`, redirected): `deploy/web.Dockerfile` builds landing + client and serves them with Caddy (`deploy/Caddyfile`: landing at `/`, client files at `/app/`, client routes rewritten to `/app/index.html`). `VITE_*` service variables are build args, baked in at build time — a change needs a redeploy.
  - `foundertown` → `api.thefoundertown.com`: `server/Dockerfile` (copies `client/public/assets/maps/` — the rooms validate against both maps; `MAP_DIR` overrides the folder). Variables: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `APP_URL=https://thefoundertown.com`, `CLOUDFLARE_TURN_KEY_ID`, `CLOUDFLARE_TURN_API_TOKEN` (+ `RESEND_API_KEY`). Keep it at one replica: rooms live in memory.
  - A new client route must be added to the `@app` matcher in `deploy/Caddyfile`.
- **Database:** `supabase/migrations/` are run by hand in the Supabase SQL editor, in order (`0001_profiles.sql`, `0002_offices.sql`). A server running against a database without 0002 still opens private lobbies, as empty offices nobody can edit.
- WebSocket `maxPayload` is raised to 32 KB (SDP offers are larger than Colyseus' 4 KB default) — keep it if the transport changes.

## Office & studio (`shared/src/office.ts`, `client/src/state/studio.ts`, `client/src/ui/Studio.tsx`)
- **A private lobby is its owner's office.** It plays on `office.tmj`, which starts empty; the owner lays out **departments** (`DEPARTMENTS`: HQ, Product, Sales, Marketing, Finance, Legal & Admin) as **spaces** — rectangles of tiles with their own carpet and furniture, no walls, never overlapping, 5×4 to 18×12 tiles, inside the map's `build` zone. The main lobby has no layout and cannot be edited.
- **The layout is the only thing stored:** `OfficeLayout = { spaces: [{ id, kind, x, y, w, h }] }`. Everything else is derived by `buildWorld(map, layout)` (pure, used by client and server): the floor of each space (terrain tile with property `floor` = department id), its furniture (`furnish`: one arrangement per department that scales with the size — add a department by adding it to `DEPARTMENTS`, an icon in `DEPT_ICONS`, a floor tile in `DEPARTMENT_FLOORS` and a chair color in `CHAIR_COLORS`, both in `scripts/lib/env.ts`), the collision grid, and one zone of kind `space` per space. The shared test furnishes every department at every size (nothing outside the space, nothing stacked, every desk reachable) — keep it passing when changing an arrangement.
- **Flow:** the room loads the saved layout with the first person in (`lobby_office` RPC, run as that user: owner name, whether the caller is the owner, layout), sanitizes it and syncs it to everyone as `state.office`. The owner's edits go store → `net/room.ts` (a `store.office` that did not come from the room is the owner's edit) → `office` message → the room sanitizes, rebuilds its grid, moves anyone now standing in furniture (`snap`) and syncs. Saving is the client's: `net/office.ts` upserts the owner's `offices` row (RLS: own row only; debounced, one request at a time). Guest mode: the server keeps layouts in memory and the owner's browser keeps `ft.office.v1`, handed to the room on join (`JoinOptions.office`).
- **Studio** (logo menu → Edit the office, enabled only in your own lobby; `/studio/<lobby>`): `view: "studio"`. `body.studio` swaps the sidebar for the studio's rail + catalog (`--studio-panel`), the same world is shown without characters under a free camera (`camera.setFree`: starts on the whole map, drag to pan, wheel zooms around the pointer, down to 0.5×). No draft: every finished edit is the office at once (seen live by visitors, saved), with undo/redo for the session.
- **Editing logic is `state/studio.ts`** (no Phaser, no network): `StudioInput` feeds it pointer positions in world px; it owns the tool (a department to place / `erase` / select), the selection, the drag, and `studio.preview` — the layout shown while something is in hand, with `fits`. A drop that does not fit is refused. `StudioOverlay` draws grid, outlines, handles and the red tint from that state; the scene rebuilds the world from `studio.preview ?? office`.
- **In the world:** `WorldView` paints space floors on a blank tile layer (`spaces`, depth −25) and recreates furniture on every `setWorld`; the tile layers are rebuilt only when the map changes (`WorldScene.loadWorld`). `SpaceChips` (icon + name above each space) are React, portaled into `.world-layer` — a DOM layer in `#game` that `WorldLayer.ts` transforms like the camera, so children are laid out in world px. Standing in a space blurs everything outside it (`FocusVeil.ts`: four `backdrop-filter` bands around the space plus one tile above it for heads — not a `clip-path` hole, which browsers do not apply to the blur). `hud.dept` puts the department icon on the zone chip; the minimap tints spaces.

## Landing page (`landing/`)
- Separate workspace package: React + three.js + Tailwind v4 + Vite (`pnpm dev:landing`, port 5180; `pnpm build:landing`). One screen: an orange page with the animated isometric city in one big rounded frame (no border), the headline (`PixelTitle.tsx`: Helvetica rasterized on the city's art-pixel grid from `city/scale.ts`, extruded in black; the real `<h1>` is screen-reader only) and the "Join now" button → `/signup` (same site in production; `VITE_APP_URL`, default `http://localhost:5173` in dev). `/signup` opens the sign-in screen on "create account" (old `?join` links still do); the flow is sign up → onboarding → town. In guest mode the same screen shows "Continue as guest" once (`ft.guest.v1`). Accents are orange `#ff6600` and black only; both texts are Helvetica.
- `src/city/voxel.ts`: the camera is fixed at (+x, +y, +z), so only three faces of a box are ever visible — `Builder` bakes the static city from those faces with flat shading (no lights), `Boxes` is an instanced pool refilled every frame. `city.ts`: the static city (roads every 10 units, 8×8 block slabs, landmarks, bridge, piers) + the places the animation needs. `life.ts`: people, traffic (lanes, lights, braking), cable cars, boats, rocket, fog. `CityCanvas.tsx`: orthographic 2:1 isometric camera, rendered at 1/px resolution and upscaled with `image-rendering: pixelated`.
- Colors come from the game's ramps (`palette.ts` re-exports `@ft/shared`). Landmarks are placed in a ring around the screen center because the headline covers the center — keep that when adding any.

## Pixel spec (summary — `shared/src/spec.ts` is the source of truth)
- Tile 32×32. Character frame 32×64, feet at row 61, anchored bottom-center.
- `pixelArt: true`, pixel-snapped camera. Never scale sprites by non-integers.
- Zoom defaults to the largest integer that fits the viewport. Trackpad pinch / two-finger scroll / mouse wheel zooms **continuously** (1–6, eased) — a deliberate exception to integer zoom, requested by the user. `render/camera.ts` positions the camera itself (no Phaser `startFollow` / `setBounds` / `roundPixels`); it snaps the view to a screen pixel only at whole zoom levels. Tile seams at fractional zoom are prevented by extruding the terrain tileset at load (`extrudedTileset` in `world/WorldView.ts`, margin 1 / spacing 2) — keep that for any new tileset. Anything drawn over the canvas in DOM must use `worldToScreen()` from `camera.ts` (not `cam.worldView`, which is rounded and jitters).
- Name tags are DOM chips (`render/NameTag.ts`, `.nametag` in `styles.css`) in a `.nametags` layer inside `#game`, positioned on the scene `RENDER` event with `worldToScreen()`. They are locked to the character: unrounded position and a CSS scale of `zoom / TAG_ZOOM` (12px text at 2×), so they grow and shrink with the world. Not Phaser text.
- Grid movement, one tile per `STEP_MS` (180 ms). 4 directions; `right` = `left` mirrored.
- Sheet template: 4 columns × 6 rows (128×384). Rows anim-major: idle_down, idle_up, idle_left, walk_down, walk_up, walk_left. Idle 4 frames, walk 4 (8 fps).
- Character art: pure black outline, key ramps for recolorable parts (skin = yellow keys, primary = magenta keys, secondary = cyan keys), fixed colors from `FIXED_COLORS`.
- Palette: extracted from the reference office screenshots (`ENV_RAMPS`/`CLOTH_RAMPS` in `shared/src/palette.ts`): cream brick floors, lavender carpets, grey-green walls, mint gardens, blue fabric, tan wood, amber/coral accents; UI navy + purple. Environment art has **no hard outlines** — flat fills, joints/patterns one shade off, objects get a soft edge in their own darkest shade. Characters keep their black outline.
- Walls match the reference perspective: a horizontal wall is the back wall of the room below — a 2-row face (`faceTop` with a thin cap line / `faceTopWindow`, then `faceBottom` with baseboard). Vertical walls are **edge walls**: a thin band split across the tile boundary (`bandRight` | `bandLeft`) plus an invisible edge in the hidden `edges` layer (`edgeW`, tile property `side=W`) → `CollisionGrid.blockEdge`; movement/pathfinding use `canStep()`, so rooms run wall-to-wall with no blocked column.
- Depth = feet / base y for characters and furniture. Ground layers < 0, `above` layer 2,000,000, debug 3,000,000.

## UI shell (React, `client/src/ui/`)
- Everything is dark: the profile card and dialogs use the same gray as the sidebar (`--surface*`/`--ink*` alias the `--chrome*` tokens). Only the avatar preview stage stays light.
- Layout: dark gray chrome (`--chrome`) with a 68px left sidebar; the game canvas (`#game`) is a rounded frame inset 8px. `body.no-sidebar` collapses the sidebar (the frame's left inset is the `--frame-left` CSS variable; Phaser's RESIZE mode follows the parent).
- **UI scale:** the whole React layer is drawn at `--ui-scale` (0.75) via `zoom` on `#ui`; CSS sizes are written pre-scale and `#game`'s insets multiply by the same variable. Inside `#ui` use `%` instead of `vw`/`vh` (viewport units ignore zoom). `.sprite` canvases counter-zoom, so `AvatarSprite`'s `scale` is real screen pixels per sprite pixel.
- **Motion:** every UI transition/animation is ≥150ms (`--t` 200ms, `--ease`) and lives in the `prefers-reduced-motion: no-preference` block at the end of `styles.css`. Panels (logo menu, profile card, dialogs) are wrapped in `Presence` (`App.tsx`), which keeps them mounted for one exit animation (`data-closing`). The sidebar stays mounted and slides out via `body.no-sidebar` while `#game`/`.frame-ui` transition `left`; Phaser's `scale.resizeInterval` is 0 so the canvas follows the frame every frame.
- **Motion:** hover/press feedback runs at 160ms (`--t`), opening and closing (panels, sidebar) at 200ms (`--t-open`, mirrored by `EXIT_MS` in `App.tsx`), both with `--ease`; they and live in the `prefers-reduced-motion: no-preference` block at the end of `styles.css` — never shorter than 150ms. The sidebar stays mounted and slides out via `body.no-sidebar` while `#game`/`.frame-ui` transition `left`; Phaser's `scale.resizeInterval` is 0 so the canvas follows the frame every frame.
- `Shell.tsx`: `Sidebar`, `LogoMenu` (logo click), `BottomBar`, `ProfileCard` (bar chip or the player's own name tag), `MapControls` (zoom +/−, minimap, debug toggle), `SidebarToggle`. `EditProfile.tsx`, `EditAvatar.tsx` are the dialogs; `AvatarSprite.tsx` draws any avatar/crop through the game's compositor (thumbnails, previews). Icons: `lucide-react`.
- `Auth.tsx` (sign-in screen, same `.ob` + `TownScene` layout as onboarding), `Onboarding.tsx`, `Social.tsx` (`LobbyChip`, `InviteDialog`, `PlayerCard`, `CallLayer` = ringing + the call panel (`.call-panel`: tiles in a grid in one dark frame, docked top-right — one row up to 3 people, then two; near-square when full; a button grows it to fill the game frame over 400ms; leave-call uses the `bar-btn danger` style), `Notice`). Before `session.status === "ready"` `App` renders only the `.screen` steps.
- Store drives it: `popover` ("menu" | "profile" | "player" + `selected`, one at a time, closed by `.popover-catch`), `modal` ("editProfile" | "editAvatar" | "invite" | "founder" | "settings" | "meeting"), `view` ("map" | "calendar" | "studio"; game input is disabled while a modal is set or the view is not the map), `office` / `build` / `studio` / `officeSave` (see Office & studio), `avatarReturn`, `sidebarOpen`, `minimapOpen`, `minimap` (floor plan published by the scene: wall tiles, thin edge walls, furniture footprints — drawn as an SVG, so it stays sharp), `zoomCmd` (UI → camera intent). Profile (name, time zone, picture) persists in `ft.profile.v1`, avatar in `ft.avatar.v1`.
- Sidebar entries and most logo-menu items are **UI only** — their systems (chat, search, notifications, billing…) are not built. Map, Calendar, Settings, Edit the office, mic, camera, invite, lobby switching, leave and sign out are real.
- **Calendar (`Calendar.tsx`, sidebar → Calendar):** a page (`.cal`) rendered inside `.frame-ui` over the game frame — the town keeps running under it and `CallLayer` stays on top. Left panel: invite card, search, Scheduled / Meeting Notes lists and a town card (`Minimap` with `onPick` + the regular `BottomBar`); right: the week grid (`HOUR_PX` per hour, sticky day header, now-line, click an empty slot or "New Meeting" → `MeetingDialog`). Date math, overlap lanes (`layoutDay`) and `dueReminders` are pure, in `shared/src/calendar.ts` (tested). Meetings are personal and **local**: `store.meetings`, saved to `ft.meetings.v1` — not in Supabase, not shared with the lobby, no Google Calendar. `state/calendar.ts` holds the actions (`saveMeeting`, `deleteMeeting`, `openMeeting`, `updateSettings`) and the reminder clock (`startReminders`: notice line + chime, 5 minutes before and at the start).
- **Settings (`Settings.tsx`, sidebar gear / logo menu):** `.dialog.settings`, section list on the left, pane on the right. `store.settings` (`ft.settings.v1`, per device): time format, week start, default meeting length, reminder toggles, mic/camera device, noise suppression, voice volume, mirror. Add a section only for something that works — no placeholder panes. `net/voice.ts` reads the device settings (`constraints()`, reopens the device when they change, `listDevices()`), and multiplies peer volume by `settings.volume`.
- `.backdrop` is a one-column grid (`minmax(0, 1fr)`), so a dialog's `max-width: 100%` holds on narrow windows.
- Edit Avatar categories (`CATEGORIES`): Character → the starter characters (`STARTERS` in `shared/src/avatar.ts`, applied in the skin tone already picked), then one per slot: Skin → face items + skin tones, Hair, Top, Jacket → outerwear, Bottom, Shoes, Hat → headwear, Glasses → face_accessory, Other → back_accessory. Every item in `items.json` is wearable; `unlock` still locks an item, but nothing uses it now.
- An item with `defaults` (ramp names) is put on in its own colors the first time; other items keep the colors already picked for the slot.

## Props (furniture) & floors
- Source sheets → `scripts/tools/build_props.py <uploads>` → `art/props/<room>/<name>.png` + `art/props/props.json` (name, file, size, tile footprint). Rooms: office, lounge, meeting, kitchen; floor textures in `art/props/floors/`.
- **All props are 32×32-tile detail.** 16px-scale sheets (interiors) are converted with Scale2x (`scale2x()`: rebuilds diagonals at 2×, no 2×2 blocks) + `reshade()` (top-left light: 1px highlight/shadow rim one palette step apart). 32px-scale sources (kitchen, walls, reference desk, reference bookshelves) are used ×1. Run `python3 scripts/tools/check_props.py` after adding props — it flags plain 2×-upscaled art and sizes outside 32px-world ranges (must be all ✓).
- Department chairs (`office_chair_<color>`) are not source art: `gen-placeholders.ts` recolors `office_chair` into `client/public/assets/furniture` (`CHAIR_COLORS`). Department carpets are terrain tiles 24–28 (`carpet()` in the terrain generator); Product uses the lavender carpet.
- **Drawn props** (`scripts/lib/desk-props.ts`): `dual_monitor`, `mac_mini`, `mouse_mat` (mat + mouse) are authored in code, pixel by pixel in the prop palette, and written by `gen-placeholders.ts` straight to `client/public/assets/furniture` (not in `art/props`, not touched by build_props.py). Footprint 0. Every desk carries them: `DESK_SETUP` in `shared/src/office.ts` (px offsets on the desk, `z` over it) is used by the office's `station()` and by the town's desks in `gen-map.ts` — change a position there, then regenerate the maps.
- **Kept assets only** (`KEEP` in build_props.py): kitchen props (counters, sinks, stove, fridge, shelf, microwave, mixer, coffee machine), office `desk` + `office_chair`, plants (`plant_tree`, `plant_small`, `plant_desk`, `plant_pot`), and the kitchen floor texture. Everything else was removed; library, lounge and meeting room are empty rooms (plants only) waiting for new art. Add props by extending `KEEP` + MANIFEST.
- Every prop is recolored to `PROP_PALETTE` (colors sampled from the reference office; mirrored in `shared/src/palette.ts`). Translucent shadows are dropped.
- `tableSet()` in `gen-map.ts` (table + chairs on four sides) is kept for when table/chair art returns.
- Map objects: footprint 0 = no collision (rugs, wall decor, counter-top items, chairs — see Sitting); prop `layer: floor` (rugs) draws under characters; object property `z` lifts items standing on counters/desks above them.
- `scripts/tools/slice_sheet.py` slices a sheet into numbered sprites + a contact sheet — use it to pick new props and add them to the MANIFEST.

## Characters
- Base body = `art/characters/reference/base_body.png` (down / up / left, 96×64) → idle frames.
- Walk = `art/characters/reference/base_walk.png` + `.json` (4 frames × down/up/left, imported from the reference recording with `scripts/tools/import_walk_reference.py <video>`; cycles anchored on the planted foot). Heads are the base head riding the whole-body bob in the JSON; legs/arms are the reference poses.
- Clothing is a **recolor of the base body's pixel classes** per frame (`classes()` in the generator): TANK → shirt, SHORTS + LEG → pants, FOOT (lowest 3 leg px) → shoes, ARM → sleeves, TORSO_SKIN (skin between the undershirt straps) → covered by every top, HAND never covered. Hood/blazer V/skirt are also recolors or anchored to these classes — no fixed-rectangle geometry from the old body. Each pixel keeps its reference shade, so clothing has the reference outline, contour and shading, and hands crossing the hips stay visible. Bulky extras (hood, skirt, backpack, hats) are drawn shapes.
- Items: `art/characters/items.json` (source) → copied to `client/public/assets/characters/items.json`. An item = slot + parts (layer + sheet) + channels (+ optional `unlock`).
- Layer draw order per direction: `LAYER_ORDER` in `shared/src/avatar.ts` (facing up, back layers move in front).
- The base body is split into `body` (torso/limbs) and `head` layers; `head` is drawn above top/outerwear so clothing never covers the chin. The chin/jaw extends below the head rows in the middle columns (`isChin` in `scripts/lib/pose.ts`: row 45 cols 10–21, row 46 cols 11–20) and is part of the head layer; shirts put the chin's cast shadow on row 47.
- The head is an oval (reference silhouette). Hair and headwear are cut from that silhouette (`fromHead`) and must not grow outside it — otherwise the head reads as round. Use `f.headReg()` for them — it copies the reference head's shade per pixel (`headShades`), so hair/hats carry exactly the reference shading; black outline only on the outer silhouette, the ramp's dark shade where hair meets skin (no black line across the forehead). Hair covers the whole back of the head down to the collar (back view) and the whole side of the head behind the face (side view: everything from `SIDE_FACE_W` = 8 columns back, in front of, behind and under the ear); only the face and ears stay skin — ears (`isEar`) are never covered by hair, including long hair.
- Exception — **voluminous hair** (`hair_swept_01`, the default): hand-authored shape templates per direction (`SWEPT` in the generator; digits = shade, edge = outline) that are 2 px taller/wider than the head, with strand lines and highlight streaks. Such items declare `partsUnderHat` (a variant clipped to the head silhouette); `itemParts(item, avatar)` in `shared/src/avatar.ts` picks it while headwear is worn — both compositors must use it.
- **Long hair** (`hair_long_02`, worn by the second starter): templates in `LONG`, drawn by the same `shapedHair()` as `SWEPT`. Its length hangs below the head (rows from `LONG_LOOSE_TOP`), so the under-hat variant clips only the rows above it.
- **Stamped items** (`Frame.stamp`): the cowgirl hat (`COWGIRL`) and the poncho (`PONCHO`) are hand-authored pixel rows per direction — `#` outline, `0`–`3` primary shades, `a`–`d` secondary shades, `s`/`w` silver — not recolors or auto-shaded regions. The hat rides the head bob and its front brim stays inside cols 4–27 (the head thumbnail); the poncho rides the body bob, and `ponchoCoversBody()` fails the build if an arm or hand sticks out of it in any frame.
- `face_02` is the default face plus lashes (two eye-colored pixels at the outer corner of each eye).
- Shading comes from the reference pixels themselves: clothing copies the body pixel's shade, hair/hats copy the head's (`headShades`). `volume: true` cel shading is only for drawn shapes (hood, skirt, backpack, cap brim).
- Compositor bakes each avatar once into a single texture (`client/src/game/avatar/compositor.ts`), cached by appearance.

## Workflow
- Work in vertical slices. Plan first, keep each slice runnable, commit when it works.
- After touching art or the generator: `pnpm assets:placeholders --force && pnpm assets:validate && pnpm tsx scripts/preview-avatar.ts`, then look at `docs/previews/`.
- After touching rendering: run the game and take a screenshot to check it — don't assume.
- Never overwrite real art with placeholders (`--force` only while all art is still generated).
- Update this file when an architecture decision changes.
