# Founder Town — instructions for Claude Code

2D pixel-art social world (top-down 3/4 view) for startup founders. Phase 1 = **engine + asset pipeline + layered characters**. Game systems (pills, missions, multiplayer) come later — don't build them unless asked.

Full spec: `docs/spec.md`. Read it before changing anything in `shared/src/spec.ts`, the layer system or the asset pipeline.

## Stack
- pnpm workspaces: `shared/` (pure TS), `client/` (Vite + Phaser 3 + React), `server/` (empty — Colyseus later), `scripts/` (asset tooling, run with tsx), `art/` (source art)
- TypeScript strict everywhere. Vitest for `shared/`. Playwright (via `/tmp`-style scripts) for visual checks.

## Commands
- `pnpm dev` — run the client (http://localhost:5173)
- `pnpm test` — unit tests (shared logic)
- `pnpm typecheck`
- `pnpm assets` — placeholders (missing files only) → map (if missing) → validate
- `pnpm assets:validate` — enforce the pixel spec on every asset; must pass before committing art
- `pnpm tsx scripts/preview-avatar.ts` — render composed avatars to `docs/previews/`
- `pnpm assets:export` — export real Aseprite art (needs Aseprite CLI)

## Architecture rules (do not break)
1. **Rendering never owns state.** `client/src/state/store.ts` is the single client store. Phaser views read logic objects; they never mutate them.
2. **Logic vs view split.** `entities/Character.ts` (logic, no Phaser) vs `entities/CharacterView.ts` (render). Same pattern for anything new.
3. **`shared/` is pure.** No Phaser, no DOM, no Node APIs. Movement, collision, pathfinding, avatar schema, palette swap and map parsing live here so the future server runs the same code.
4. **Input → intents.** `InputController` produces directions/clicks; the scene applies them to logic.
5. **The map is data.** Rooms, collisions, furniture, spawns and zones come from Tiled (`client/public/assets/maps/town.tmj`). Never hardcode world content in code. The starter map is the office (open office, kitchen, library, lounge, meeting room) generated by `scripts/gen-map.ts --force`; after that, edit it in Tiled.
6. **UI is React over the canvas.** Panels, menus and builders are DOM, not Phaser.

## Pixel spec (summary — `shared/src/spec.ts` is the source of truth)
- Tile 32×32. Character frame 32×64, feet at row 61, anchored bottom-center.
- `pixelArt: true`, pixel-snapped camera. Never scale sprites by non-integers.
- Zoom defaults to the largest integer that fits the viewport. Trackpad pinch / two-finger scroll / mouse wheel zooms **continuously** (1–6, eased) — a deliberate exception to integer zoom, requested by the user. `render/camera.ts` positions the camera itself (no Phaser `startFollow` / `setBounds` / `roundPixels`); it snaps the view to a screen pixel only at whole zoom levels. Tile seams at fractional zoom are prevented by extruding the terrain tileset at load (`extrudedTileset` in `world/WorldView.ts`, margin 1 / spacing 2) — keep that for any new tileset. Anything drawn over the canvas in DOM must use `worldToScreen()` from `camera.ts` (not `cam.worldView`, which is rounded and jitters).
- Name tags are DOM chips (`render/NameTag.ts`, `.nametag` in `styles.css`) in a `.nametags` layer inside `#game`, positioned on the scene `RENDER` event with `worldToScreen()`. They are locked to the character: unrounded position and a CSS scale of `zoom / TAG_ZOOM` (12px text at 2×), so they grow and shrink with the world. Not Phaser text.
- Grid movement, one tile per `STEP_MS` (180 ms). 4 directions; `right` = `left` mirrored.
- Sheet template: 4 columns × 6 rows (128×384). Rows anim-major: idle_down, idle_up, idle_left, walk_down, walk_up, walk_left. Idle 4 frames, walk 4 (8 fps).
- Character art: pure black outline, key ramps for recolorable parts (skin = yellow keys, primary = magenta keys, secondary = cyan keys), fixed colors from `FIXED_COLORS`.
- Palette: extracted from the reference office screenshots (`ENV_RAMPS`/`CLOTH_RAMPS` in `shared/src/palette.ts`): cream brick floors, lavender carpets, grey-green walls, mint gardens, blue fabric, tan wood, amber/coral accents; UI navy + purple. Environment art has **no hard outlines** — flat fills, joints/patterns one shade off, objects get a soft edge in their own darkest shade. Characters keep their black outline.
- Walls match the reference perspective: a horizontal wall is the back wall of the room below — a 2-row face (`faceTop` with a thin cap line / `faceTopWindow`, then `faceBottom` with baseboard). Vertical walls are **edge walls**: a thin band split across the tile boundary (`bandRight` | `bandLeft`) plus an invisible edge in the hidden `edges` layer (`edgeW`, tile property `side=W`) → `CollisionGrid.blockEdge`; movement/pathfinding use `canStep()`, so rooms run wall-to-wall with no blocked column.
- Depth = feet / base y for characters and furniture. Ground layers < 0, `above` layer 2,000,000, debug 3,000,000.

## UI shell (React, `client/src/ui/`)
- Everything is dark: the profile card and dialogs use the same gray as the sidebar (`--surface*`/`--ink*` alias the `--chrome*` tokens). Only the avatar preview stage stays light.
- Layout: dark gray chrome (`--chrome`) with a 68px left sidebar; the game canvas (`#game`) is a rounded frame inset 8px. `body.no-sidebar` collapses the sidebar (the frame's left inset is the `--frame-left` CSS variable; Phaser's RESIZE mode follows the parent).
- **UI scale:** the whole React layer is drawn at `--ui-scale` (0.75) via `zoom` on `#ui`; CSS sizes are written pre-scale and `#game`'s insets multiply by the same variable. Inside `#ui` use `%` instead of `vw`/`vh` (viewport units ignore zoom). `.sprite` canvases counter-zoom, so `AvatarSprite`'s `scale` is real screen pixels per sprite pixel.
- **Motion:** every UI transition/animation is ≥150ms (`--t` 200ms, `--ease`) and lives in the `prefers-reduced-motion: no-preference` block at the end of `styles.css`. Panels (logo menu, profile card, dialogs) are wrapped in `Presence` (`App.tsx`), which keeps them mounted for one exit animation (`data-closing`). The sidebar stays mounted and slides out via `body.no-sidebar` while `#game`/`.frame-ui` transition `left`; Phaser's `scale.resizeInterval` is 0 so the canvas follows the frame every frame.
- **Motion:** hover/press feedback runs at 160ms (`--t`), opening and closing (panels, sidebar) at 200ms (`--t-open`, mirrored by `EXIT_MS` in `App.tsx`), both with `--ease`; they and live in the `prefers-reduced-motion: no-preference` block at the end of `styles.css` — never shorter than 150ms. The sidebar stays mounted and slides out via `body.no-sidebar` while `#game`/`.frame-ui` transition `left`; Phaser's `scale.resizeInterval` is 0 so the canvas follows the frame every frame.
- `Shell.tsx`: `Sidebar`, `LogoMenu` (logo click), `BottomBar`, `ProfileCard` (bar chip or the player's own name tag), `MapControls` (zoom +/−, minimap, debug toggle), `SidebarToggle`. `EditProfile.tsx`, `EditAvatar.tsx` are the dialogs; `AvatarSprite.tsx` draws any avatar/crop through the game's compositor (thumbnails, previews). Icons: `lucide-react`.
- Store drives it: `popover` ("menu" | "profile", one at a time, closed by `.popover-catch`), `modal` ("editProfile" | "editAvatar"; game input is disabled while set), `avatarReturn`, `sidebarOpen`, `minimapOpen`, `minimap` (floor plan published by the scene: wall tiles, thin edge walls, furniture footprints — drawn as an SVG, so it stays sharp), `zoomCmd` (UI → camera intent). Profile (name, time zone, picture) persists in `ft.profile.v1`, avatar in `ft.avatar.v1`.
- Sidebar entries, most logo-menu items, mic/camera and "Connect apps" are **UI only** — their systems (chat, calendar, billing, calls…) are not built.
- Edit Avatar categories map to slots (`CATEGORIES`): Skin → face items + skin tones, Jacket → outerwear, Hat → headwear, Glasses → face_accessory, Other → back_accessory.

## Props (furniture) & floors
- Source sheets → `scripts/tools/build_props.py <uploads>` → `art/props/<room>/<name>.png` + `art/props/props.json` (name, file, size, tile footprint). Rooms: office, lounge, meeting, kitchen; floor textures in `art/props/floors/`.
- **All props are 32×32-tile detail.** 16px-scale sheets (interiors) are converted with Scale2x (`scale2x()`: rebuilds diagonals at 2×, no 2×2 blocks) + `reshade()` (top-left light: 1px highlight/shadow rim one palette step apart). 32px-scale sources (kitchen, walls, reference desk, reference bookshelves) are used ×1. Run `python3 scripts/tools/check_props.py` after adding props — it flags plain 2×-upscaled art and sizes outside 32px-world ranges (must be all ✓).
- **Kept assets only** (`KEEP` in build_props.py): kitchen props (counters, sinks, stove, fridge, shelf, microwave, mixer, coffee machine), office `desk` + `office_chair`, plants (`plant_tree`, `plant_small`, `plant_desk`, `plant_pot`), and the kitchen floor texture. Everything else was removed; library, lounge and meeting room are empty rooms (plants only) waiting for new art. Add props by extending `KEEP` + MANIFEST.
- Every prop is recolored to `PROP_PALETTE` (colors sampled from the reference office; mirrored in `shared/src/palette.ts`). Translucent shadows are dropped.
- `tableSet()` in `gen-map.ts` (table + chairs on four sides) is kept for when table/chair art returns.
- Map objects: footprint 0 = no collision (rugs, wall decor, counter-top items); prop `layer: floor` (rugs) draws under characters; object property `z` lifts items standing on counters/desks above them.
- `scripts/tools/slice_sheet.py` slices a sheet into numbered sprites + a contact sheet — use it to pick new props and add them to the MANIFEST.

## Characters
- Base body = `art/characters/reference/base_body.png` (down / up / left, 96×64) → idle frames.
- Walk = `art/characters/reference/base_walk.png` + `.json` (4 frames × down/up/left, imported from the reference recording with `scripts/tools/import_walk_reference.py <video>`; cycles anchored on the planted foot). Heads are the base head riding the whole-body bob in the JSON; legs/arms are the reference poses.
- Clothing is a **recolor of the base body's pixel classes** per frame (`classes()` in the generator): TANK → shirt, SHORTS + LEG → pants, FOOT (lowest 3 leg px) → shoes, ARM → sleeves, TORSO_SKIN (skin between the undershirt straps) → covered by every top, HAND never covered. Hood/blazer V/skirt are also recolors or anchored to these classes — no fixed-rectangle geometry from the old body. Each pixel keeps its reference shade, so clothing has the reference outline, contour and shading, and hands crossing the hips stay visible. Bulky extras (hood, skirt, backpack, hats) are drawn shapes.
- Items: `art/characters/items.json` (source) → copied to `client/public/assets/characters/items.json`. An item = slot + parts (layer + sheet) + channels (+ optional `unlock`).
- Layer draw order per direction: `LAYER_ORDER` in `shared/src/avatar.ts` (facing up, back layers move in front).
- The base body is split into `body` (torso/limbs) and `head` layers; `head` is drawn above top/outerwear so clothing never covers the chin. The chin/jaw extends below the head rows in the middle columns (`isChin` in `scripts/lib/pose.ts`: row 45 cols 10–21, row 46 cols 11–20) and is part of the head layer; shirts put the chin's cast shadow on row 47.
- The head is an oval (reference silhouette). Hair and headwear are cut from that silhouette (`fromHead`) and must not grow outside it — otherwise the head reads as round. Use `f.headReg()` for them — it copies the reference head's shade per pixel (`headShades`), so hair/hats carry exactly the reference shading; black outline only on the outer silhouette, the ramp's dark shade where hair meets skin (no black line across the forehead). Hair covers the whole back of the head down to the collar (back view) and the whole side of the head behind the face (side view: everything from `SIDE_FACE_W` = 8 columns back, in front of, behind and under the ear); only the face and ears stay skin — ears (`isEar`) are never covered by hair, including long hair.
- Exception — **voluminous hair** (`hair_swept_01`, the default): hand-authored shape templates per direction (`SWEPT` in the generator; digits = shade, edge = outline) that are 2 px taller/wider than the head, with strand lines and highlight streaks. Such items declare `partsUnderHat` (a variant clipped to the head silhouette); `itemParts(item, avatar)` in `shared/src/avatar.ts` picks it while headwear is worn — both compositors must use it.
- Shading comes from the reference pixels themselves: clothing copies the body pixel's shade, hair/hats copy the head's (`headShades`). `volume: true` cel shading is only for drawn shapes (hood, skirt, backpack, cap brim).
- Compositor bakes each avatar once into a single texture (`client/src/game/avatar/compositor.ts`), cached by appearance.

## Workflow
- Work in vertical slices. Plan first, keep each slice runnable, commit when it works.
- After touching art or the generator: `pnpm assets:placeholders --force && pnpm assets:validate && pnpm tsx scripts/preview-avatar.ts`, then look at `docs/previews/`.
- After touching rendering: run the game and take a screenshot to check it — don't assume.
- Never overwrite real art with placeholders (`--force` only while all art is still generated).
- Update this file when an architecture decision changes.
